## 2. 产物之间的关系

```text
预编译库（仓库自带）
  libunitree_sdk2.a + libddsc.so + libddscxx.so + onnxruntime + mujoco
                    │
                    │ cmake --install
                    ▼
        ~/.local/deps/usr  （头文件 + 库 + cmake 配置）
                    │
        ┌───────────┴────────────┐
        ▼                        ▼
  g1_ctrl（控制器）          unitree_mujoco（仿真器）
  ├ libg1_controller_lib.a   ├ mujoco 模型/场景
  ├ libcnpy_lib.a            └ /dev/input/js0（可选手柄）
  └ policy.onnx/deploy.yaml
        │                        │
        └────── DDS（interface=lo, domain_id=0）──────┘
               仿真器 → rt/lowstate / rt/wirelesscontroller
               控制器 → rt/lowcmd
```

关键关系：

- `g1_ctrl` 负责 **ONNX 推理、观测拼接、动作后处理、FSM**，把关节目标写到 `rt/lowcmd`。
- `unitree_mujoco` 负责 **物理仿真和传感器回传**，订阅 `rt/lowcmd`，发布 `rt/lowstate` 和手柄 `rt/wirelesscontroller`。
- 两者只通过 **DDS** 解耦，没有进程内调用关系。
- `jstest` 只读 `/dev/input/js0` 打印轴和按键，**不在闭环里**。
- `onnxruntime` 只有 `g1_ctrl` 需要；`mujoco` 只有仿真器需要。

## 4. 跑仿真的是哪个文件

**仿真器本体是 `unitree_rl_mjlab547/simulate/build/unitree_mujoco`。**

但“跑仿真闭环”需要两个进程：

```text
unitree_mujoco   ← 仿真环境 + 物理 + DDS 回传
g1_ctrl          ← 策略推理 + FSM + DDS 下发
```

`run_all.sh` 就是把这两个进程一起拉起来。只启动 `unitree_mujoco` 只能看到机器人站着/下落，不会有策略控制。

## 5. 手动编译 + 手动调用仿真

每个新终端都要先 `source env.sh`，否则会报 `libddsc.so.0: not found`。

### 5.1 环境

```bash
cd /home/newname/文档/Trae-CN/temp_20261022_01/robot_rl
source env.sh
```

### 5.2 SDK（只有 `~/.local/deps/usr/lib/cmake/unitree_sdk2` 不存在时才需要）

```bash
cmake -S unitree_sdk2_547 -B unitree_sdk2_547/build \
      -DCMAKE_INSTALL_PREFIX="$HOME/.local/deps/usr" \
      -DBUILD_EXAMPLES=OFF
cmake --build unitree_sdk2_547/build --parallel "$(nproc)"
cmake --install unitree_sdk2_547/build
```

### 5.3 编译 g1_ctrl

```bash
cmake -S unitree_rl_mjlab547/deploy/robots/g1 \
      -B unitree_rl_mjlab547/deploy/robots/g1/build \
      -DCMAKE_PREFIX_PATH="$HOME/.local/deps/usr"
cmake --build unitree_rl_mjlab547/deploy/robots/g1/build --parallel "$(nproc)"
```

产物：`unitree_rl_mjlab547/deploy/robots/g1/build/g1_ctrl`

### 5.4 编译仿真器

```bash
cmake -S unitree_rl_mjlab547/simulate \
      -B unitree_rl_mjlab547/simulate/build \
      -DCMAKE_PREFIX_PATH="$HOME/.local/deps/usr"
cmake --build unitree_rl_mjlab547/simulate/build --parallel "$(nproc)"
```

产物：`unitree_mujoco`、`jstest`

### 5.5 启动闭环（3 个终端）

```bash
# 终端 0（可选，没有物理手柄时）
sudo python3 scripts/virtual_xbox_gamepad.py

# 终端 1：先启动仿真器
cd /home/newname/文档/Trae-CN/temp_20261022_01/robot_rl
source env.sh
./unitree_rl_mjlab547/simulate/build/unitree_mujoco

# 终端 2：再启动控制器
cd /home/newname/文档/Trae-CN/temp_20261022_01/robot_rl
source env.sh
./unitree_rl_mjlab547/deploy/robots/g1/build/g1_ctrl --network=lo
```

顺序不能反：`g1_ctrl` 启动后会 `wait_for_connection()` 等 `rt/lowstate`，仿真器没起来就会一直等。

手动编译完也可以直接用：

```bash
./scripts/run_all.sh --no-build
```

它会帮你处理日志、手柄检测和退出清理。

## 6. 三个容易踩的坑

1. **`LD_LIBRARY_PATH`**：`g1_ctrl` 和 `unitree_mujoco` 都依赖 `~/.local/deps/usr/lib` 下的 `libddsc.so.0`、`libddscxx.so.0`，不 `source env.sh` 就起不来。
2. **配置文件路径绑定可执行文件位置**：`g1_ctrl` 通过 `/proc/self/exe` 从 `build/` 推回 `robots/g1/config`；仿真器从 `build/` 推回 `simulate/config.yaml`。不要把二进制单独拷走。
3. **DDS 必须同域同网卡**：`simulate/config.yaml` 是 `domain_id: 0`、`interface: "lo"`，`g1_ctrl` 必须配 `--network=lo`；否则两边互相看不到。另外仿真器需要图形显示，否则会报 `ERROR: could not initialize GLFW`。
