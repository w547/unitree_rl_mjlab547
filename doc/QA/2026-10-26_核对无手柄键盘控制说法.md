# 问题

② 没有手柄，仿真能跑吗？能，而且官方和社区都有成熟方案。

mjlab 的部署栈本身支持键盘控制。在 sim2sim 模式下，仿真窗口获得焦点后可以直接用键盘操作：1 FixStand、2 Walk、W/S/A/D 前后左右、Q/E 转向、0 或 x Passive。另外，unitree_mujoco 的摇杆集成也可以显式关闭：设置 use_joystick: 0，仿真器就会在没有游戏手柄的情况下正常运行。社区教程也专门讲过“如何在没有手柄的情况下使用键盘控制 MuJoCo 中的 G1 机器人移动”。所以手柄不是仿真的前置条件，只是可选输入设备。

# 回答

## 结论

这段分析**大方向对，细节不对，不能直接照做**。具体说：

- “手柄不是仿真的前置条件，只是可选输入设备”——这个结论对。
- “`use_joystick: 0` 仿真器就能正常运行”——只对一半：仿真器能启动、DDS 能连，但不会发布手柄数据，部署端 FSM 只能停在 Passive，进不了 FixStand / Velocity。
- “mjlab 部署栈本身支持键盘控制，窗口焦点后按 1 FixStand、2 Walk、0/x Passive”——**当前这份 `unitree_rl_mjlab` 不是这样**。仓库里没有 1/2/0/x 这套 FSM 键盘映射，现有 `Keyboard` 读的是 `g1_ctrl` 终端的 stdin，不是 MuJoCo 窗口，而且只接到速度观测，不接 FSM。
- “社区教程存在”——可能有，但通常是针对某个 fork、旧版本或改过 `unitree_mujoco` 的补丁，不能当作当前仓库的使用说明。

## 为什么 `use_joystick: 0` 不等于闭环

从仿真器代码看：

- [unitree_sdk2_bridge.h](file:///home/newname/文档/Trae-CN/temp_20261022_01/robot_rl/unitree_rl_mjlab/simulate/src/unitree_sdk2_bridge.h#L29-L41)：`use_joystick == 1` 才创建 `XBoxJoystick` / `SwitchJoystick` / `KeyboardJoystick`。
- [unitree_sdk2_bridge.h](file:///home/newname/文档/Trae-CN/temp_20261022_01/robot_rl/unitree_rl_mjlab/simulate/src/unitree_sdk2_bridge.h#L242-L246)：只有 `wireless_controller->joystick` 非空才发布 `rt/wirelesscontroller`。
- `lowstate` 的 `wireless_remote` 也只有在 joystick 非空时才写入。

所以 `use_joystick: 0` 时：

```text
仿真器：正常启动，物理和 DDS 都在跑
rt/wirelesscontroller：不发布
rt/lowstate.wireless_remote：全 0
g1_ctrl：连接正常，FSM: Start Passive
结果：按什么键都进不了 FixStand / Velocity
```

这适合“只看模型、看物理”，不适合验证策略闭环。

## 当前工程实际可用的做法

已经在仿真器输入层加了 `joystick_type: "keyboard"`：

```text
键盘（MuJoCo 窗口）
  → GLFW 回调
  → KeyboardJoystick（继承 UnitreeJoystick）
  → rt/lowstate.wireless_remote / rt/wirelesscontroller
  → g1_ctrl 的 FSM 和 velocity_commands
```

部署工程 `g1_ctrl` 一行没改，物理手柄仍然保留。键位是：

- `W/S/A/D`：前后左右；`Q/E`：转向
- `↑↓←→`：方向键
- `J/K/U/I`：A/B/X/Y
- `F/G`：LT/RT；`R/T`：LB/RB
- `F + ↑`：FixStand；`G + J`：Velocity；`T + J`：Mimic；`F + K`：Passive

这套方案实现的就是那段分析想要的“键盘闭环”，但键位不是 1/2/0/x。如果确实想要 1/2/0/x 的布局，需要在仿真器里加一层别名映射（把 1 映射成 LT+Up 的一次脉冲，2 映射成 RT+A，0/x 映射成 LT+B），或者直接改部署端 FSM 的触发源；前者不改部署工程，后者会偏离真实部署语义。
