# Sim2Sim 站立后摔倒排查（G1-29dof / unitree_rl_mjlab）

现象：仿真窗口里机器人先站着（手臂自然下垂），随后整个机器人摔倒。

结论：**摔倒发生在策略接管之前，不是 deploy 配置错位、也不是策略本身的问题**。
本仓库的 `scene_g1.xml` + `policy.onnx` 用 deploy.yaml 的增益可以直接稳定站立，并按指令精确行走；
摔倒由启动时序 + FSM 初始状态（Passive）共同造成，且倒地后无法再起身，只能重启仿真。

## 1. 逐项核对（按排查清单）

| 检查项 | 期望 | 实测 | 结论 |
|---|---|---|---|
| 关节顺序 | SDK 顺序 = XML 顺序 = `joint_ids_map` | `joint_ids_map` 为 0..28；`scene_g1.xml` 的 `<jointpos>`/`<jointvel>`/`<motor>` 顺序为左腿 0-5、右腿 6-11、腰 12-14、左臂 15-21、右臂 22-28 | 对齐 |
| 默认姿态 | `default_joint_pos` = 训练 `HOME_KEYFRAME` | 29 项逐项相等（hip -0.1 / knee 0.3 / ankle -0.2 / shoulder_pitch 0.35 / elbow 0.87 / shoulder_roll ±0.18） | 对齐 |
| PD 增益 | deploy.yaml 与训练 actuator 一致 | 7520_14 40.2/2.6、7520_22 99.1/6.3、5020 14.3/1.8、4010 16.8/1.1、踝与腰 28.5/1.8（= 2×5020） | 对齐 |
| 动作缩放 | `0.25 × effort_limit / stiffness` | 除腕部外逐项吻合（hip_pitch 0.55、hip_roll/knee 0.35、踝/腰/臂 0.44）；腕 0.07 vs 0.0744（约 -6%） | 腕部小偏差，不影响平衡 |
| 观测定义 | 98 维、同 flat 任务 | base_ang_vel(3)+projected_gravity(3)+velocity_commands(3)+gait_phase(2)+joint_pos_rel(29)+joint_vel_rel(29)+last_action(29) = 98；ONNX 输入 `obs[1,98]`、输出 `actions[1,29]` | 对齐 |
| gait_phase | `sin/cos(2π·phase)`，\|cmd\|<0.1 置零 | deploy `observations.h` 与训练 `mdp/observations.py::phase` 公式一致 | 对齐 |
| 控制周期 | 训练 50 Hz = 部署 50 Hz | 训练 `decimation=4 × timestep 0.005`；部署 `step_dt: 0.02`；仿真 bridge PD 1 kHz | 对齐 |

模型差异（会影响 sim2sim 保真度，但不是本次摔倒原因，因为策略在该模型上仍能站立/行走）：

- `scene_g1.xml` 用 `<default>` 给全部 29 关节加了 `damping=0.05 armature=0.01 frictionloss=0.2`，训练用的 `g1.xml` 没有这些默认值（mjlab 按执行器单独设 armature：5020≈0.0036、7520_14≈0.0102、7520_22≈0.0251、4010≈0.0043）。
- 足端接触：仿真每只脚 4 个 r=5 mm 的球（支撑域 x∈[-0.081, 0.099]），训练每只脚 7 个 capsule（condim 3，friction 0.6）。
- 仿真 `timestep=0.002`（scene 无 `<option>`），训练 0.005。
- `scene_g1.xml` 无 `<keyframe>`：出生位姿是 `qpos=0`（直腿站立、手臂下垂，pelvis z=0.793，足底接触球离地约 1 mm）。

## 2. 无 GUI 复现（关键证据）

用仓库自带的 `libmujoco.so 3.3.6` + `libonnxruntime 1.22` 写了一个临时 C++ 复现工具（`/tmp/sim2sim_probe.cpp`，不属于工程），直接加载 `scene_g1.xml` 和 `policy.onnx`，按 `unitree_sdk2_bridge.h` 的 PD 公式、deploy.yaml 的 KP/KD/SCALE/QDEF、50 Hz 策略步进复现整条链路。

| 场景 | 结果 |
|---|---|
| 控制器未连接（`ctrl=0`，即 lowcmd 还没发布） | 0.75 s 俯仰 0.96 rad，2.5 s 倒地（pelvis 0.06 m） |
| FSM 初始 Passive（kp=0, kd=3） | 1.0 s pelvis 0.63 / 俯仰 1.06 rad，1.5 s 基本倒地 |
| Passive 3 s（已倒地）→ FixStand 2 s | FixStand 把 pelvis 从 0.51 拉到 0.17，**仍是躺地，起不来** |
| Passive 0.1 s → FixStand 0.4 s → 策略接管（t=0.5 s） | pelvis 稳定 0.784，动作范数 ≈0.9，**站住** |
| Passive 0.1 s → FixStand 0.8 s → 策略接管（t=0.9 s，俯仰 0.21） | 策略能救回来并站稳 |
| Passive 0.1 s → FixStand 1.2 s → 策略接管（t=1.3 s，俯仰 0.72） | **接不住，摔倒** |
| FixStand 保持（从 HOME 姿态） | 1.0 s 俯仰 0.38，1.5 s 倒地 |
| 零动作（q_des=QDEF、策略增益） | 1.4 s 倒地 |
| 速度指令 vx=0.1 | 8 s 前进 0.868 m（0.108 m/s），pelvis 0.78 稳定 |
| 速度指令 vx=0.6 | 7.5 s 前进 4.37 m（0.58 m/s），pelvis 0.772–0.780 |

两条量化结论：

- **策略正常**：站立（pelvis ≈0.784 m，默认姿态）与速度跟踪（0.1 / 0.6 m/s 误差 <2%）都成立，优于清单里 mjlab 基准的 4.82 m 量级。
- **FixStand 不能静态自稳**：总质量 33.34 kg，CoM 高约 0.67 m，倒立摆重力刚度 `m·g·h ≈ 219 N·m/rad`；FixStand 踝关节 kp=40（双脚合计 80），远小于所需值，所以从好姿态也只能撑约 1 s，2 s 插值还没走完就会前倾倒地。零动作测试 1–2 s 摔倒同理，是“关节 PD 无法静态自稳 + 策略反馈缺失”的正常现象，不能据此判定策略坏。

## 3. 根因排序

1. **启动时序（主因）**：`scripts/run_all.sh` 先起仿真器、`sleep 3` 后才起 `g1_ctrl`；这段时间 lowcmd 还没发布，`d->ctrl=0`，机器人相当于自由落体，约 2.5 s 内必倒地。等 `g1_ctrl` 连上并停在 Passive 时，机器人已经躺在地上。
2. **FSM 初始状态是 Passive**：`CtrlFSM::start()` 取 `states[0]`（Passive，kp=0/kd=3），即使控制器先连上也同样不提供支撑，1 s 内倒地。
3. **FixStand 只有约 1 s 窗口**：踝 kp=40 << 219，且 2 s 线性插值期间身体持续前倾。若等插值“走完”再按 G+J，必然在 FixStand 里倒下。
4. **倒地不可恢复**：FixStand 是插值到目标位姿，没有起身逻辑；策略也未训练起身。实测倒地后按 F+↑ / G+J 都只能继续躺地，必须重启仿真。
5. 次要：腕部动作缩放 0.07 vs 0.0744（-6%）；足端接触、joint armature/damping/frictionloss、timestep 与训练模型不一致（影响保真度，不影响本次结论）。

## 4. 建议

**A. 先按现有代码验证（不改动任何文件）**

1. 先起 `g1_ctrl --network=lo`（它会停在 `Waiting for connection to robot...`），再起仿真器。
2. 仿真窗口出现后先点一下窗口让其获得焦点（键盘手柄只收 GLFW 窗口的按键，终端里按无效；窗口失焦还会清空按键）。
3. 顺序要“先按住 F，再按 ↑”（`LT + up.on_pressed` 是边沿触发，先按 ↑ 再按 F 不会触发）。
4. 进入 FixStand 后 **1 s 内** 按住 G 再按 J 进 Velocity，不要等 2 s 插值结束。
5. pelvis 稳定在 ≈0.78 m 后再按 W 行走。

**B. 启动保持（推荐的最小改动）**

在 `simulate/src/unitree_sdk2_bridge.h` 里给“控制器未连接 / lowcmd 全零”阶段加一个固定 PD 保持（kp≈200、kd≈5，目标是出生位姿），直到收到非零 kp 的 lowcmd 为止。这样机器人不会无控下落，操作者可以从容按键，现象与真机（悬吊或已站好）一致。

**C. 一键脚本**

`scripts/run_all.sh` 去掉/缩短 `g1_ctrl` 前的 `sleep 3`，或改为先起 `g1_ctrl` 再起仿真器（`wait_for_connection` 会等待 lowstate）。

**D. 若希望 FixStand 自身能站住**

从 HOME 出生姿态实测，踝 kp 需约 300 才能在 MuJoCo 里撑住（kp=150 仍会 2.7 s 倒地）；从直腿出生姿态插值到 HOME 会把身体持续前推，仅调 kp 不够。建议同时把出生姿态改成 HOME（加 `<keyframe>`）并把 `ts` 缩短。

**E. 长期**

把 `scene_g1.xml` 的足端接触几何、joint armature、timestep 对齐训练用的 `g1.xml`，再评估 sim2sim 保真度。

## 5. 复现方法（临时工具，不入库）

```bash
# 编译
g++ -O2 -std=c++17 -o /tmp/sim2sim_probe /tmp/sim2sim_probe.cpp \
  -I unitree_rl_mjlab/simulate/mujoco/include \
  -I unitree_rl_mjlab/deploy/thirdparty/onnxruntime-linux-x64-1.22.0/include \
  -L unitree_rl_mjlab/simulate/mujoco/lib -lmujoco \
  unitree_rl_mjlab/deploy/thirdparty/onnxruntime-linux-x64-1.22.0/lib/libonnxruntime.so.1.22.0

# 参数: scene policy t_passive t_total mode(2=Passive→FixStand→策略) <home_init> <fix_stand_s> <vx> [ankle_kp]
/tmp/sim2sim_probe \
  unitree_rl_mjlab/src/assets/robots/unitree_g1/xmls/scene_g1.xml \
  unitree_rl_mjlab/deploy/robots/g1/config/policy/velocity/v0/exported/policy.onnx \
  0.1 8 2 0 0.4 0.1
```
